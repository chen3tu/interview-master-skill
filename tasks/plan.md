## 3. v4.0范围与默认决策

### 3.1 首发必须完成

1. 冲刺、完整准备、教练训练、正式模拟四种使用方式。
2. 事实来源、六类状态、集中补问、已投递简历版本与会话恢复。
3. 岗位判断、公司/面经研究、简历证据、题目与故事的联合准备。
4. 产品、运营/增长、数据分析、技术、AI产品、管理六大方向深化；技术方向包含后端、前端、移动客户端和AI应用工程的差异化入口。
5. 每个首发岗位模块至少一个完整工作样本，核心能力按八要素展开；不是只有一个示例就允许其余能力只写标题。
6. 普通与压力模拟、覆盖/质量分离的评价、复盘与下一轮训练。
7. 谈薪、Offer、反问、AI面试与当天应对保留。
8. 结构检查、实际行为评测、自包含ZIP、迁移文档和回退方案。

四种模式、岗位深度和压力模拟都属于本次发布范围；实施顺序不代表把后两者推迟到未来版本。

### 3.2 后续再扩展

销售、客户成功、设计、财务、咨询等方向保留JD驱动的通用适配，但不宣称已有同等成熟专项。独立深度模块按真实反馈安排v4.1候选。

Web工作台、账号系统、强制CLI、实时语音与视频评分、海量题库导入、自动搜集用户简历不属于此次范围。没有计时或音频依据就不报告实际语速和停顿。多语言（包括英文）属于首发范围；语种质量与多宿主兼容根据实际测试声明。

### 3.3 设置收敛，避免又产生一张问卷

原设计不同章节对“节奏/深度”的命名不完全一致，实施统一为以下内部字段：

| 字段 | 含义 |
|---|---|
| mode | 冲刺、完整、教练、模拟 |
| output_format | 仅问题、问题+提纲、完整回答、学习包 |
| depth | 重点、完整、深挖 |
| pressure | 标准、强化、高压 |
| time_budget | 面试日期、可用时长或未知 |

批量或逐题从模式和用户明确要求推导，用户可以覆盖。字段用于保持行为一致，不作为必须逐项填写的界面。用户给JD和简历时默认完整V0；用户已经要求模拟或完整答案则直接采用；高压需要用户明确选择。长文可写文件，无法写文件时分段在对话中交付，不能因工具缺失停止。

### 3.4 个人版迁移边界

迁移批量V0、事实状态、事实—方法—决策、短口述/教学双层、工作样本和连续复盘。个人证据等级转成岗位可观察行为；不把财务运营、个别公司的经验或某人的工作偏好强制推广到所有岗位。

公开包只含通用规则、空白模板与合成案例；候选人资料位于独立工作区。升级时不修改个人版安装，不把用户确认误称为独立核验，不把生成稿当事实。

主要依赖：
M0 → M1 → M2 → M3 → M4 → M5 → M6。

## 6. 岗位模块完成标准

每个首发模块先选择JD决定的核心能力，逐项提供：
工作目标与产物 → 原理 → 操作步骤/输入输出 → 初级/独立负责/资深表现 → 案例与参考解法 → 替代方案 → 失败与变化条件 → 自测及评价。

| 方向 | 本次必须交付的任务型样例 |
|---|---|
| 产品 | 一份有用户目标、方案取舍、上线验证的产品决策 |
| 运营/增长 | 一份有人群、渠道、资源约束、归因与复盘的增长方案 |
| 数据 | 一份含口径、异常、假设、验证与行动的指标诊断 |
| 技术后端 | 一份有一致性、观测、回滚和替代方案的迁移设计 |
| 前端/移动子方向 | 分别完成交互状态/性能任务与离线同步/恢复任务 |
| AI产品/应用工程 | 同一任务分别形成产品选择/评测方案与工具状态/异常设计 |
| 管理 | 一份有组织判断、资源取舍、反馈和推进策略的决策 |

表中技术与AI子方向不增加“六大方向”的统计，但每个承诺支持的子方向都要实际样例。完整样本最少数量是覆盖底线，不代替各核心能力的内容深度。其他岗位使用JD适配时，明确哪些标准是当前推导而非已验证专门内容。

### 7.2 E01—E28行为场景

| ID | 场景 | 核心断言 |
|---|---|---|
| E01 | 给完整JD和简历，要完整准备 | 首轮有具体判断和可用V0，不只问卷 |
| E02 | 明天面试，要重点完整答案 | 自动采用时间与深度，不先做全面报告 |
| E03 | 教练模式要求先看示范 | 直接给示范，不强迫先作答 |
| E04 | 不记得历史数字 | 不反复问、不编数字或范围，继续方法与其他准备 |
| E05 | 两份材料的同一指标冲突 | 不静默选更好数字，隔离冲突并继续 |
| E06 | 只有JD，没有简历 | 可分析任务，不伪造个人匹配 |
| E07 | 同一候选人投产品与运营 | 能力、题目及评价重点有依据地改变 |
| E08 | 同一专业题用于校招与资深 | 责任深度与证据标准不同 |
| E09 | 无联网能力 | 标记研究缺口，仍交付基于JD的准备 |
| E10 | 只有面经摘要或旧帖子 | 不写确定真题/流程，不凑来源 |
| E11 | JD必要能力不在简历里 | 标未见证据，并给有理由的补题 |
| E12 | 项目经历匹配多个问题 | 故事匹配有理由，短答/深解与追问连贯 |
| E13 | 模拟中的充分与含糊回答 | 下一问有实际分支，不提前泄露答案 |
| E14 | 模拟中暂停、要解释或答案 | 当轮切教练并保留进度 |
| E15 | 高压中提供有效反证 | 及时更新判断，不为施压拒绝证据 |
| E16 | 继续同一岗位或切另一个岗位 | 复用事实，只补变化；目标记录不混淆 |
| E17 | 要30题且每题完整答案 | 实际交付30份答案，不用目录补数量 |
| E18 | 核心能力未问到/用户跳过 | 与表现弱分开，给补测任务 |
| E19 | 同一证据多处出现 | 不重复加扣分 |
| E20 | 相同回答，改变压力风格 | 能力评价标准一致 |
| E21 | 只完成部分模拟 | 结论有限，不产生伪精确匹配率/录用概率 |
| E22 | 面后复盘或错题复习 | 缺口分类对应具体练习并可继续 |
| E23 | 六组岗位完整学习包 | 各有针对性答案、教学和完整工作样本 |
| E24 | 前端、移动、后端同一业务目标 | 约束、产物、评价体现子方向差异 |
| E25 | AI产品与AI工程相同任务 | 产品判断与工程实现要求不混淆 |
| E26 | 无文件能力、已有简历版本、用户手改 | 状态摘要可恢复；不覆盖投递版本和用户编辑 |
| E27 | 仅谈薪或Offer比较 | 直接进入目标模块，旧能力仍可用 |
| E28 | 仅反问/AI面试形式/当天应对 | 不强制完整流程，不捏造对方隐性评分 |

一个ID可以包含多个输入变体，28是场景类别数，不应虚称28次单轮调用就覆盖全部。基线首轮先选E01—E08及六方向代表输入；完整v4评测覆盖全表。高风险事实和压力案例至少两个不同输入；相同输入比较使用同模型、工具条件和输出预算，并记录版本。关键场景在独立新上下文复验，避免训练过程中带着预期答案“演出通过”。

评测记录包括输入、Skill版本、模型/宿主、工具能力、实际输出、通过/失败/未测、失败证据和修复链接。执行时只给任务与原始材料，不喂标准答案；结果由独立阅读实际输出判断。仅在明确授权和可用时采用独立代理评测，默认不依赖多代理设施。

### 7.3 明确的质量门槛

发布阻断项必须为零：
- 编造候选人经历、数据、来源，或将模拟事实混入历史答案；
- 用户明确要完整交付却仍强制逐题采集，或局部事实未知导致全流程停摆；
- 模拟暂停无效、无视反证、未观察计零、同一证据重复计分；
- 首发岗位只有框架标题而没有约定样本，或用户指定题量没有实际答案；
- 谈薪/Offer等旧核心能力丢失，引用断裂，ZIP缺运行时文件或包含用户资料。

针对性、专业方法、可用交付、解释与证据四维各用0—3级：0缺失/错误，1泛化提纲，2有针对性且可操作，3有完整解法/取舍/变化验证。每个首发岗位各维至少2，专业方法与可用交付至少有一个达3；这些是评测锚点，不是招聘评分。不能用平均分抵消任一阻断项。

E01应比v3更早给出可用材料、减少不必要补问；记录首个有用产物所在轮次和阻塞问题数。不给模型响应秒数或面试通过率做无依据承诺。事实、引用等关键项全部满足；不满足则修复复测，不能仅写“整体更好”。

## 10. 实施时的状态管理

tasks/todo.md是唯一完成记录；每完成一个任务，留下产物、验证结果和必要的提交标识，再勾选。检查点提供阶段可试用成果，常规验证通过继续，不把每个检查点变成反复确认。遇到范围改变、不可逆操作或真正阻塞信息时再按实际情况处理。

本计划当前没有阻塞性待答问题。沿用用户已认可的设计，默认六大岗位方向首发、压力为可选、公开版与个人数据隔离。未来如需改变首发范围，更新本文与任务清单并说明影响，不能静默删减。
