# Technical role router

Read the JD to choose a subdirection:
- API, data services, distributed state: [backend](role_backend.md).
- Browser interaction, rendering, accessibility: [frontend](role_frontend.md).
- Mobile app, offline state, constrained devices: [mobile](role_mobile.md).
- LLM application, retrieval, tools and evaluation: [AI application](role_ai_application.md).

For unfamiliar specialties, build provisional criteria from the actual task and verify relevant primary sources; do not substitute a backend system-design interview for all technical jobs.

Common loop: clarify requirements → model inputs/state → propose a simple solution → reason about correctness/constraints → test failures → explain alternatives and delivery.
Coding practice: ask for a clear approach and implementation when requested; verify with representative and boundary inputs if execution exists. Without execution, say review-only. Never claim code passed tests it did not run.
Technical interview scope may include debugging, code review, API design, algorithms or architecture. Select proportionally to the JD and round, not a fixed sequence.

Ownership: distinguish authoring, integrating, reviewing and operating. Lines of code are not a measure of contribution. A hypothetical design is not evidence of production delivery. Evaluate communication separately from language fluency.
