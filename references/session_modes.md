# Preparation modes

## Defaults without a configuration interview

Derive settings from the user's message: mode, output_format, depth, pressure, time_budget and language preferences. A setting is a convenience, not a required form. If no preference is stated and sufficient JD/candidate material exists, start complete preparation. A single knowledge question is answered directly.

| Mode | First useful output | Interaction |
|---|---|---|
| Sprint | Role priorities, introduction/main story, highest-risk answers, one-page recap | Prioritize by available time; batch essential missing facts |
| Complete | Role judgment and usable V0 preparation body | Produce first, consolidate questions afterward; incrementally revise |
| Coach | Method or worked example, then targeted practice | User-first or example-first as requested |
| Mock | One job-relevant question | Wait for an answer; adapt; debrief at the end or on request |

Output formats: questions only; questions with outlines; complete spoken answers; learning packet (spoken answer + teaching + work sample). Depth: focused, complete, deep. These do not automatically change mode. A sprint can contain one deep answer; complete preparation need not become one-question-at-a-time coaching.

Pressure defaults to standard. Use challenge or high pressure only when the user requests it. It changes constraints and follow-up intensity, not the standard of evidence.

## V0 acceptance

With sufficient material, the first response includes a concrete role judgment, a tailored introduction or main-story draft, and prioritized answers with clear evidence boundaries. Continue to the promised scope, in a file or numbered sections. Do not stop after announcing that V0 will be made later.

Ask normally up to five high-value factual questions at the end; fewer is better if sufficient. Do not ask to fill every schema field. If a critical contradiction affects an answer, omit that claim while completing unaffected sections. An unknown role can require a routing question; an unknown metric cannot hold the entire session hostage.

## Switching and resuming

- "Show me the answer" during a mock: stop simulation now, explain, preserve the current question and observations.
- "Continue the mock": resume after the explanation; do not treat the shown model answer as independent candidate performance.
- "Only English from now on": switch the requested output/conversation scope; retain facts and topic state. See [language rules](language_and_locale.md).
- "Don't ask one by one": batch preparation immediately.
- Returning candidate: inspect the saved summary, ask only what changed and reuse confirmed material.

Checkpoint: target, settings, facts changed, outputs delivered, actual observations, pending question, next priorities. [State contract](evidence_and_state.md) defines persistence. File access is optional; produce a copyable summary when unavailable.
