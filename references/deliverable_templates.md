# Deliverables

Translate all user-facing headings into the chosen output language. These structures are defaults, not mandatory sections for a narrow request.

## Complete preparation packet

1. Target and one-page judgment: role priorities, supported strengths, consequential gaps.
2. Company facts that change preparation, with source/date and uncertainty.
3. JD → task → capability → evidence → question matrix.
4. Tailored introduction and motivation answers.
5. Main projects: facts, contribution boundary, short/standard/deep versions and follow-up responses.
6. Prioritized questions and actual answer prose; crucial ones also get teaching, alternatives and failure cases.
7. Role learning section: concepts, procedure, tradeoffs and misconceptions.
8. A complete work sample with input, constraints, output, reference approach, alternative, changed conditions and evaluation.
9. Pressure preparation examples (hidden while actually simulating).
10. Reverse questions and round-specific emphasis.
11. Time-budgeted practice plan, recap and consolidated unresolved facts.

For a fully specified request, deliver its scope. If no count is stated, choose enough distinct questions to cover the essential work; a typical full packet may contain 15–25, with 8–12 deeply developed. This is not a quota. State what is deeply developed versus briefly answered. A request for 30 complete answers requires 30 answer bodies.

## Sprint

Role priorities; introduction; strongest relevant story; critical questions with usable answers; biggest factual/skill risk; reverse questions; short practice sequence. Skip company trivia and broad reading lists. Time estimates are suggestions, not measured response timing.

## One question

Why it matters → spoken answer → evidence boundaries → explanation/decision logic → likely follow-ups. If the user asks questions only, do not attach answers. If no personal history is supplied, explicitly give a hypothetical example or neutral method rather than inventing first-person achievements.

## Debrief

Observed answer excerpt → capability criterion → what worked → specific gap → improved answer → next exercise. Include observed vs unobserved coverage. Separate language feedback if requested. Do not write a mock transcript for an interview that did not occur.

## Completion and updates

Record delivered vs pending sections; material facts needing confirmation; practice not yet attempted; actual observations. File output: complete body plus a short chat summary and link. Chat-only output: numbered sections and a copyable continuation summary. Do not stop at an outline.

Preserve user changes. On new facts regenerate only affected sections, identify changes and carry the same fact IDs across translated versions.
