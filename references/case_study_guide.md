# Case and work-sample practice

Use [module standard](competency_module_standard.md) and the chosen [role](role_catalog.md).

## Set the task
Specify goal, inputs, constraints, expected artifact and evaluation dimensions. Explicitly label synthetic information. Ask only clarifications that change the approach. A candidate may state reasonable assumptions and proceed, then test them.

## Choose learning or assessment
In learning mode, provide a complete worked solution when requested, explain why each step is needed, then change a constraint for practice.
In mock/assessment, provide the task and inputs only. Let the candidate work, probe decisions, and show a reference solution afterward or on pause. Do not make "try first" compulsory when the user asks to be taught.

## Review the artifact
Check whether it solves the stated problem, respects constraints, explains alternatives, handles failures and defines validation. Accept different defensible solutions. For coding, run permitted representative tests if available; otherwise label review-only. For business analysis check units, arithmetic and attribution. For architecture trace state, responsibilities and recovery.

## Variation
Change one meaningful factor (budget, population, reliability requirement, data quality, deadline or stakeholder goal). Observe what changes in the solution and why. A memorized framework without an adapted decision is not sufficient.

## Output
Task and assumptions → candidate artifact if actually supplied → evidence-based review → complete reference solution → alternative → change response → next drill.
Never invent that the candidate submitted or passed a work sample.
