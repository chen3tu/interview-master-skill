# R05 AI 产品面试准备

说明：六个案例共享本评估者上下文；直接读取指定 v3 运行文件，未安装技能。以下为合成 JD 的预测题与教学方案。

**岗位与证据判断。** 三年产品经验、FAQ 检索原型及二十例人工检查，支持原型探索和初步质量意识；不足以证明账户操作上线、安全控制或规模化效果。岗位重点是价值评估、自动化范围、人审设计、监控闭环。二十例只能帮助发现问题，不能作为低风险上线证据。补齐检查标准、失败例和原型个人职责，明确未上线真实账户自动变更。

**针对性题：** 从回答问题到修改账户，首发做什么，怎样决定可上线？考察风险取舍和人机协作。

**可直接练习的答案，约两分钟：**
“我会先选高频、低损失、可逆的单项修改，例如语言偏好，暂不开放密码、登录邮箱、支付信息、权限和注销。我的经验止于 FAQ 检索原型及二十例人工检查，没有真实账户自动变更上线经验，下面是方案判断。

首发让 AI 理解意图和生成修改建议，账户身份、权限、参数及执行都由确定性服务校验。先向用户展示当前值和新值，经明确确认后进入人工审核；审核通过才调用白名单接口。模型不能从对话里任意指定账户，也不能凭自信程度跳过授权。接口用幂等标识，执行后查询实际状态；超时显示处理中，不能把生成一句成功当作修改成功。

我会以真实任务完成、纠错返工和总服务成本判断价值，同时把未授权操作作为停止条件。测试覆盖正常、歧义、恶意输入、越权和超时，并从历史授权数据中留出独立评测集。先影子运行，再小流量全量人审；只有证据足够才评估减少人审。我更看重可控地完成任务，而不是自动化率。”

**工作样本：首发决策卡，数字为教学门槛。** 选“账户语言偏好修改”，不同时开放第二种动作。流程为登录态核验 → 识别意图 → 白名单参数校验 → 展示变更 → 用户确认 → 人审 → 幂等执行 → 状态核验 → 留存审计记录与恢复入口。确认失效、值已变化或权限撤销时重新确认；重复请求不得重复副作用。

先构建五百条独立测试，按风险分层，攻击与越权样本单列，不能用大量简单 FAQ 稀释。拟定门槛：全部执行路径通过权限与幂等测试；未授权执行为零；低风险意图及参数正确率至少百分之九十九，并报告区间与样本覆盖。零次观测不证明零风险，任一严重事件仍否决上线。

首发百分之一流量、全部人工审核，与表单流程比较任务完成率、处理时长、人工分钟数、推理和返工成本；观察一周只是初步判断，量不足继续收集。未授权、错误账户或审计缺失立即停写，转只读和人工处理；普通质量不达标也不扩大范围。只在同类低风险范围验证达标，不能外推到账户安全操作。

**替代与层级。** 若表单更快更便宜，采用“AI 找入口、用户填表”；意图歧义则人工澄清。初级看能否定义任务、错误与评测集；资深还须建立风险预算、责任边界、审计恢复和单位经济性。追问：人审错了怎么办？高置信模型仍越权怎么办？如何迁移到账户邮箱修改？危险点是把二十例通过当成生产质量保证。
